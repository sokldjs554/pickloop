## 2. 회사가 공개한 제품과 작업 흐름

[PyBrain AI 공식 제품 소개](https://www.pybrain.ai/)에 따르면 **Py PACKR**는 박스 조립에서 테이핑·라벨링까지 포장 공정을 자동화하며, **Py PICKR**는 상품을 자율 집품해 포장 라인으로 공급하는 모바일 매니퓰레이터다. **Py LOADR**는 컨테이너 하역용 컨베이어 연계 로봇이다. 비전 인식과 3D 파지, WMS 표준 API 연결, 처리량·가동시간·운영 로그 대시보드도 소개한다.

공식 FAQ는 오류 감지 후 파지점 재샘플링 또는 라벨 재출력 같은 재시도를 설명하고, 이벤트와 이미지를 함께 남겨 추적한다고 밝힌다. 이는 **회사 공개 설명**이며 이번 조사로 자체 검증한 성능은 아니다. 공식 사이트의 비용 절감·연속 운영·주문 규모 홍보 수치를 PickLoop 성능 근거로 사용하지 않는다. [공식 FAQ](https://www.pybrain.ai/#faq)

이 설명으로부터 PickLoop에 적용할 **설계 추론**은 다음과 같다.

1. WMS 주문에 해당하는 작업 ID를 발급하고 대상 품목을 지정한다.
2. 고정형 셀에서 관측→품목 확인→위치 추정→파지 계획→흡착→들어 올림→운반→박스 안 해제→배치 확인을 먼저 완결한다.
3. 실패 원인을 관측·계획·그리퍼·통신 단계로 나눠 기록하고, 재관측·재계획·제한된 재시도 또는 보류로 종결한다. 이미지·로봇 상태·압력·로그를 동일 실행의 시각으로 연결한다.
4. 모바일 확장은 셀 진입 자원 예약→이동→도킹 확인→피킹→셀 해제→다음 작업으로 연결한다. SLAM·실제 도킹 접촉·충전 전류 검증을 생략했다면 그 상태를 한계로 적는다.

이 흐름은 공개 제품 방향에서 유도한 프로젝트 설계이며 회사의 내부 순서도·제어 구조·장치 프로토콜을 입수했다는 뜻이 아니다. 박스 조립, 테이핑, 라벨 인쇄를 구현하지 않는 경우 PACKR 전체 재현으로 소개하지 않는다. 공개 페이지에서 세부 로봇 모델, WMS API 스키마, PLC 레지스터, 충전기 사양은 확인되지 않았다.

## 4. 첫 화면에 적용할 검토 기준

- 상단: 현재 SKU·주문/작업 ID, 실행 모드(실시간 시뮬레이션 / 기록 재생 / 실물), 종료 상태(완료·복구 중·보류).
- 중앙: 실제 시뮬레이터 작업 장면과 그 실행에서 얻은 RGB-D 관측. 카메라 타임스탬프와 관측 나이를 표시한다.
- 주변: BT 진행, 밸브·압력·부착 상태, 실패 단계·이유 코드·재시도 횟수, 시간순 이벤트.
- 하단: 재생 시각과 로그 접근. 기준/복구 비교는 같은 seed·초기 상태·장애 설정을 확인할 수 있어야 한다.
- 기록 재생에서는 조건 변경이 새 물리 실행을 계산하는 것처럼 보이면 안 된다. 실물 미연결 상태를 명시하고, 지원하지 않는 버튼은 비활성화하거나 제거한다.

## 5. 증거와 확인 범위

조사 중간 자료는 `/workspace/work/research/`에 있다. `sources.json`은 URL·수신 상태·확인일·해시를, `wanted-395998-job-fields.json`은 원문에서 선택한 채용 필드를 저장한다. 원문 HTML에는 사이트 공통 스크립트도 포함되므로 실행 산출물과 분리한다. `requirements-index.json`은 위 ID의 기계 판독용 목록이다.

Wanted 원문과 직행 재게시의 주요업무·자격요건·우대 항목은 일치했다. 회사 YouTube는 검색 서비스에서 제한되어 동영상을 재생·검증하지 못했다. 회사 자체 운영 대시보드의 실제 공개 스크린샷도 확인하지 못했다. 공식 사이트가 해당 기능을 설명한다는 사실과, 그 UI를 직접 관찰했다는 사실을 구분한다.
