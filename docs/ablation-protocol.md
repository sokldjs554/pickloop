# 동일 예산 절제 실험 명세

기존 120회 결과의 1회 기준/3회 복구 비교로는 추가 시도와 복구 판단의 효과를 분리할 수 없다. 해당 결과는 `runs/final`에 과거 결과로 보존한다. 새 실험은 `runs/ablation-heldout`에 별도로 저장한다.

| 정책 | 최대 시도 | 실패 후 목표 좌표 | 실패 후 운반/복귀 높이 |
|---|---:|---|---:|
| baseline | 1 | 해당 없음 | 0.30m |
| naive | 3 | 마지막 유효 목표 재사용 | 0.30m |
| reobserve | 3 | RGB-D에서 다시 계산 | 0.30m |
| recovery | 3 | RGB-D에서 다시 계산 | 0.40m |

세 재시도 정책은 최대 시뮬레이션 60초, wall 90초의 동일 예산을 쓴다. 같은 중지/압력/충돌/관측 신선도 검사를 유지하며 불확실한 장치 출력, 취소, 충돌, 시간 초과는 추가 시도하지 않는다. 안전 정지는 예산 초과 후에도 끝까지 수행하고 실제 총 시간에 포함한다. 물체를 압력으로 확인해 잡고 있으면 재관측/접근/흡착 단계를 건너뛴다. naive도 유효 목표를 한 번도 얻지 못했다면 관측을 재시도한다. 세 정책의 실제 소모 시간은 다를 수 있으며 같은 시간까지 무의미하게 기다리지는 않는다.

`naive→reobserve`는 좌표 재관측, `reobserve→recovery`는 재시도 경로 높이 변경을 분리한다. `naive→recovery`는 두 요소를 합친 효과다. 제시한 특정 정책들의 비교이며 단순 재시도의 모든 변형이나 최적 제어보다 우수하다는 뜻은 아니다. grasp 후보 최적화·능동 시점 변경·온라인 보정 추정은 구현하지 않았다.

## 조건과 동결

개발 seeds 200..209, 최종 seeds 3000..3011. 최종 12 seed × 12 장애 조건 × 4 정책 = 576회. 최초 개발 점검 중 stop-policy 소스가 변경되어 자동 동결 검사가 부분 배치를 중단했다. 부분 개발 결과는 최종 통계에서 제외한다. 최종 배치에는 소스/모델/조건 해시 일치 검사를 적용하고 결과를 본 후 조정하지 않는다.

`conditions.CONDITION_BOUNDS`에 모든 범위를 공개했다. 개발과 최종은 배치 영역, 회전, 깊이 잡음, 보정 편차, 흡착 허용 오차, 압력, 질량, 마찰, 장애물 높이 및 장애 시간대가 다르다. 이는 통제된 합성 분포 이동이며 실물과 같은 분포라고 주장하지 않는다. 모델은 기존 appearance.pt로 고정한다.

장애는 시도 번호/정책 이름과 무관한 절대 시뮬레이션 시간표에 따른다. 같은 seed의 모든 정책은 같은 초기 물리 상태와 조건 파일을 사용한다. 정책이 다른 시각에 관측하는 경우는 같은 외란 시간표의 서로 다른 지점을 관측하는 것이며, 정책-환경 상호작용으로 포함한다. 센서 노이즈는 seed+20ms 시각 구간으로 결정되어 화면 기록 호출이 난수 소비를 바꾸지 않는다.

occlusion은 센서 영상 ROI를 가리는 모사이며 실제 가림 물체 동역학은 아니다. suction 조건은 압력/접촉/힘 기준과 공급 중단을 적용한 모사다. 기존 drops 카운터는 공급/힘 제한에 의한 강제 분리도 포함하므로 모두 공중 낙하였다는 뜻이 아니다.

## 지표와 원문

모든 원본 결과를 집계한다. 성공은 알려진 주문 SKU의 영상 배치 확인 2회, 압력 해제, 별도 물리 정답의 올바른 SKU·안정·분리를 모두 만족해야 한다. 영구 실패/미등록 주문도 전체 완료율 분모에 포함한다. 조건별 표와 seed별 원문을 함께 제공한다.

비교 차이와 정책별 완료율의 95% 구간은 seed 단위 군집 부트스트랩 10,000회로 계산한다. 같은 seed의 12조건을 독립 표본으로 취급하지 않는다. 12개 군집의 작은 합성 평가이며 실물 성능 보증이나 현장 처리량으로 사용하지 않는다.

공개 화면 대표 재생은 결과와 무관하게 첫 최종 seed3000의 normal/suction_once/suction_permanent/drop/path_blocked/unknown/calibration_error, 4정책으로 지정했다. 전체 평가 원문은 별도로 공개한다. 재생은 같은 조건/소스/모델로 다시 기록하고 초기 정답·최종 성공·원인·재시도·시뮬레이션 시간을 원평가와 대조한다. 렌더링 wall 시간은 성능 통계에 섞지 않는다.

## 재현

```bash
.venv/bin/python -m pickloop.experiment --out runs/reproduced-ablation
.venv/bin/python -m pickloop.experiment --out runs/ablation-heldout --aggregate
.venv/bin/python scripts/record_ablation.py runs/ablation-heldout --out runs/reproduced-replay
.venv/bin/python scripts/export_ablation.py runs/ablation-heldout runs/reproduced-replay --dest web/data
```

최초 명령은 빈 출력 폴더를 요구한다. 부분 배치를 자동 이어붙이거나 원본을 덮어쓰지 않는다.
