# 미등록 상품 앞면의 제품명 재시험

같은 원본 16장을 Chromium 파일 선택창에 넣었을 때, 미등록 근거를 표시한 사진은 7장에서 9장으로 늘었습니다. 7장은 여전히 판정을 보류했습니다. 두 버전 모두 등록 상품명을 잘못 표시한 사진과 피킹 주문을 잘못 확정한 사진은 각각 0장이었습니다.

| 공개 사진 | 이전 판정 | 이번 판정 |
|---|---|---|
| 블러드오렌지 · Open Food Facts 기여자 사진 | 근거 부족 | 앞면의 BLOOD와 ORANGE를 읽어 미등록 제품군으로 표시 |
| 오렌지·망고 · Kesko 상품 사진 | 근거 부족 | 앞면의 ORANGE와 MANGO를 읽어 미등록 제품군으로 표시 |

공개 데모에서도 노트북의 기본 입력 두 장에 대해 같은 판정이 표시됐습니다. [공개 데모 실행 기록](hosted.jsonl)

두 원본을 보고 판독 규칙을 개발했습니다. 이 수치는 같은 원본을 다시 읽은 결과입니다. 새로 촬영한 사진에서의 성공률은 별도 측정이 필요합니다. [사진별 결과](browser.jsonl) · [수정 전 결과](../final.jsonl) · [원본 URL과 출처](../labels.csv)

## 판정 조건

바코드를 찾지 못했고 기존 포장 판독도 결론을 내리지 못한 경우에만 앞면의 색 글씨를 다시 읽습니다. 세로 사진 가운데서 어두운 포장 면이 연속으로 보일 때 붉은 글씨를 분리합니다. 해당 영역에서 두 맛 단어가 위아래로 정렬되어야 합니다. 바로 위에 인쇄된 SELECTED와 CITRUS 또는 BLEND의 위치도 확인합니다. 굽은 글씨 일부가 뭉개진 경우에도 제목의 두 단어 중 하나와 두 맛 단어 전체가 읽혀야 합니다. 사진에서 미등록 근거가 나오면 주문은 보류합니다.

## 대조 시험

- 등록 상품이 담긴 기존 매장 사진 60장을 새 판독 단계에 직접 넣었습니다. 59장은 포장 면 조건에서 제외됐고, 1장은 글씨 검사로 넘어갔습니다. 미등록으로 잘못 판정한 경우는 0장이었습니다. [사진별 구성요소 시험](registered-component.csv)
- 브라우저 파일 선택창에서 두 원본의 JPEG 재저장본, 제품명을 가린 사진, 등록 사과주스를 옆에 붙인 합성 장면을 각각 시험했습니다. 합성·변형 사진은 독립 촬영 실적에서 제외했습니다. 다른 대조 입력으로 등록 바코드, 동시 바코드, 이웃 포장 및 기존 등록 상품 사진을 사용했습니다. [브라우저 대조 기록](controls.jsonl)
- 두 JPEG는 각각 원본을 흰 바탕에 합성해 Pillow JPEG 품질 91로 저장했습니다. 가림 시험에서는 세로 좌표 39.4~49.9% 영역을 가렸습니다. 이웃 포장은 830×1200 흰 배경의 왼쪽에 등록 사과 사진 RR-08be70619c12080f, 오른쪽에 시험 상품을 넣었습니다. 두 입력을 각각 400×1190 안에 비율을 유지해 배치했습니다.
