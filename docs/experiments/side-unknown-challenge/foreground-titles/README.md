# 미등록 상품 16장 재시험

앞면 글씨를 읽어 미등록 근거를 표시한 사례가 6장 늘었습니다. 기존 원본 16장에서 미등록 근거를 제시한 사진은 9장 → 15장, 근거 부족으로 보류한 사진은 7장 → 1장입니다. 등록 상품 오인과 잘못된 피킹 주문은 두 버전 모두 0건입니다. 개선한 여섯 장은 모두 개발 중 확인한 사진입니다. [사진별 브라우저 판정](browser.jsonl) · [이전 결과](../printed-titles/browser.jsonl) · [원본·출처·정답](../labels.csv)

| 상품 | 앞면에서 확인한 글씨 |
|---|---|
| 사과·엘더플라워 | APPLE 아래 줄의 ELDERFLOWER |
| 사과·배·키위·라임 | CRUSH 아래 두 줄에 APPLE, PEAR, KIWI, LIME |
| 사과·만다린·당근 | 병 표면을 따라 휜 글자를 펴서 읽은 APPLE, MANDARIN과 다음 줄의 CARROT |
| 단일 레드자몽 | SELECTED CITRUS 계열 표시와 두 줄의 RED GRAPEFRUIT |
| 오렌지 모닝 | ORANGE 아래의 MORNING |
| 스무스 오렌지 대용량 | SMOOTH ORANGE와 같은 포장 하단에 인쇄된 숫자 1,75 및 단위 LITER |

핀란드 사과 1 L는 보류했습니다. 사진의 APPLE 표기는 등록된 스웨덴 사과와 겹치며 등록 규격을 가를 바코드가 보이지 않습니다. 옆면의 제조사·언어 표기만으로 이 팩의 고유 상품 코드를 확정할 근거도 확보하지 못했습니다.

## 오인과 촬영 조건

기존 판독에서 바코드와 포장 판정 모두 단서를 찾지 못한 경우에만 앞면 제품명을 추가로 확인합니다. 가운데 있는 GOD 표기와 3줄짜리 로고의 검은 바탕·노란 과일 무늬를 확인하고 로고 너비를 기준으로 제품명 영역을 제한합니다. 포장 사이 흰 틈, 제목의 줄 배치, 단위와 소수점도 검사합니다. 제품군 결과만으로 주문이 확정되는 경우는 없습니다.

- 등록 상품 사진 60장을 새 판독 단계에 직접 넣었을 때 미등록 판정은 0장이었습니다. [등록 대조 기록](registered-component.csv)
- 파일 선택창으로 대조 입력 36개를 시험했습니다. 새 사례 6개에서 제품명을 가린 6장과 등록 사과를 나란히 붙인 6장이 모두 보류됐습니다. 1.75 L 표기에서 소수점이나 단위를 가린 두 사진도 보류됐습니다. JPEG 품질 90으로 재저장한 6장 중 사과·만다린·당근, 엘더플라워, 오렌지 모닝 3장에서 미등록 근거가 유지됐습니다. 기존 대조 입력 16개도 이전의 상품·주문 판정과 일치했습니다. [대조 기록](controls.jsonl)
- 같은 상품 코드의 다른 Open Food Facts 원본 9장을 추가로 시험했습니다. 여기에는 뒷면 성분·영양표, 포장의 일부, 다른 언어의 앞면이 포함됩니다. **미등록 근거 0/9장**, 근거 부족 보류 9장, 잘못된 등록 이름·주문 0건입니다. 이 9장은 기존 16장의 집계에 포함하지 않았습니다. [원본 주소](supplement-sources.csv) · [브라우저 판정](supplement.jsonl)

기본 노트북은 엘더플라워와 네 과일 혼합 두 장을 실행합니다. 두 번째 코드 셀에서 `FULL_SET = True`로 바꾸면 전체 16장의 판정을 재현할 수 있습니다. [Colab에서 열기](https://colab.research.google.com/github/sokldjs554/pickloop/blob/main/docs/experiments/side-unknown-challenge/printed-titles/replay.ipynb)
